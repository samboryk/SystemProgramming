Система контролю версій Git

Огляд розподіленої системи контролю версій: принципи роботи, архітектура, ключові команди для щоденної розробки та підсумковий сертифікат.

📖

1. Що таке СКВ та Git

За даними Вікіпедії:

Система керування версіями (СКВ, англ. Version Control System, VCS) — програмне забезпечення для полегшення роботи зі змінною інформацією (вихідним кодом програм, текстовими документами, кресленнями тощо). СКВ дозволяє зберігати історію змін, порівнювати різні редакції, відкочуватися до попередніх станів і забезпечує паралельну командну роботу без перезапису коду колег.

Git (вимовляється «ґіт») — це найпопулярніша у світі розподілена система керування версіями файлів та коду з відкритим кодом. Її створив у квітні 2005 року Лінус Торвальдс (автор ядра Linux) після відмови власників комерційної системи BitKeeper надавати безкоштовну ліцензію спільноті Linux.

«Лінус Торвальдс іронічно зауважив щодо назви: "Я самозакоханий егоїст, тому називаю всі свої проекти на власну честь. Спочатку був Linux, тепер — Git" (в англійському сленгу слово "git" означає "неприємна, вперта людина")».

🏛️ Централізовані СКВ (CVS, SVN)

Існує один головний сервер-сховище. Якщо він недоступний або пошкоджений — розробники не можуть фіксувати коміти або ризикують втратити всю історію проекту.

🌐 Розподілені СКВ (Git)

Кожен розробник клонує репозиторій повністю: разом із усією історією правок, гілками та тегами. Будь-яка локальна копія є повноцінним резервним сховищем.

⚡

2. Основні можливості та переваги Git

Завдяки своїй оригінальній архітектурі, створеній для розробки ядра Linux з тисячами контриб'юторів, Git забезпечує низку визначальних переваг:

🚀 Висока швидкодія

Майже всі операції (перегляд історії log, порівняння diff, фіксація commit) виконуються миттєво на локальному диску без мережевих затримок.

🌿 Дешеве і легке гілкування

Створення нової гілки в Git — це запис лише 41 байта (хеш-вказівник на коміт). Перемикання та злиття (merge) відбуваються майже миттєво.

🔒 Криптографічна цілісність даних

Кожен файл, каталог та коміт хешуються алгоритмом SHA. Неможливо непомітно змінити бодай один символ чи дату коміту без зміни всього ланцюжка хешів.

📦 Область підготовки (Staging Area / Index)

Проміжний буфер між робочим каталогом та історією. Дозволяє формувати акуратні, атомарні коміти, додаючи лише обрані зміни.

🔌 Автономність (Офлайн-режим)

Розробник може повноцінно працювати в поїзді, літаку чи без інтернету: створювати гілки, робити коміти, переглядати історію, а синхронізацію виконати пізніше.

🌍 Глобальний стандарт індустрії

Git підтримується всіма хмарними платформами (GitHub, GitLab, Bitbucket) та глибоко інтегрований у всі сучасні редактори (VS Code, JetBrains тощо).

💻

3. 10 базових команд роботи в Git

Найважливіші команди, необхідні для щоденної практичної роботи розробника. Натисніть кнопку Копіювати, щоб швидко використати команду в терміналі.

git init
1. Ініціалізація нового репозиторію
Коментар: Створює новий порожній Git-репозиторій у поточному каталозі. З'являється прихована папка .git, що містить усі структури метаданих, конфігурацію та об'єкти історії.
git clone <url_репозиторію>
2. Клонування існуючого репозиторію
Коментар: Завантажує повну копію віддаленого проекту (з GitHub, GitLab тощо) на ваш комп'ютер разом з усією історією комітів та налаштованим віддаленим джерелом origin.
git status
3. Перевірка статусу файлів
Коментар: Показує поточний стан робочого каталогу та індексу (staging area): які файли змінено, які підготовлено до коміту (staged), а які ще не відстежуються (untracked).
git add <файл> або git add .
4. Додавання змін до області підготовки (Staging Area)
Коментар: Переносить зміни із робочої директорії в індекс. Команда git add . індексує абсолютно всі змінені та нові файли у поточному каталозі для включення в наступний коміт.
git commit -m "Повідомлення коміту"
5. Фіксація змін (створення коміту)
Коментар: Створює знімок стану (snapshot) підготовлених файлів у базі репозиторію. Прапорець -m додає обов'язковий змістовний коментар про те, що саме було змінено або виправлено.
git branch -M main
6. Керування гілками та встановлення головної гілки
Коментар: Команда git branch показує список гілок, а комбінація -M main примусово перейменовує поточну гілку на main (сучасний стандарт найменування замість застарілого master).
git switch <назва_гілки>
7. Перемикання та створення гілок
Коментар: Сучасний аналог git checkout. Дозволяє безпечно перейти на іншу гілку, а команда git switch -c <ім'я> одночасно створює нову гілку і перемикається на неї.
git merge <назва_гілки>
8. Злиття гілок (Merge)
Коментар: Інтегрує історію вказаної гілки у вашу поточну активну гілку. Якщо в однакових рядках файлів є суперечливі зміни, Git створює стан конфлікту для ручного вирішення.
git push -u origin main
9. Відправка змін на віддалений сервер
Коментар: Вивантажує ваші локальні коміти на віддалений сервер (GitHub/GitLab). Прапорець -u (upstream) пов'язує локальну гілку з віддаленою для подальших простих викликів git push.
git pull origin main
10. Отримання та злиття оновлень з сервера
Коментар: Одночасно завантажує найновіші зміни з віддаленого сервера (fetch) та зливає їх (merge) у поточну робочу гілку, актуалізуючи вашу копію проекту.
